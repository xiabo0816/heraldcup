# 今晚就来社区 / Components And Patterns

## 1. 组件原则

- 先统一行为，再允许主题差异
- 一张卡只承担一个核心任务
- 异步数据区域必须定义 loading、empty、error 三态
- 列表页优先统一高度，详情页优先信息完整
- 后台组件优先密度、对比和风险表达
- 组件使用前先查变体矩阵，不允许页面私自发明 variant、size、tone、state
- 展示页组件允许非对称拼接，但拼接必须来自既有组件的合法组合，不允许为了“像官网”造视觉壳组件
- 全站组件都要服务“不规则大色块”母题：组件既是信息单元，也是块面边界和交互动效的载体
- Dota 2 题材下，组件首先服务对象识别和内容判断，其次才服务材质和世界观装饰

## 3. 组件文档

### Button

用途：

- 主 CTA、次 CTA、后台确认动作

何时使用：

- 页面主路径明确时使用实体按钮

何时别用：

- 仅作页面跳转目录时，优先文本链接或轻链接卡

属性：

- variant: primary | secondary | ghost | danger
- size: sm | md | lg
- state: default | hover | active | focus-visible | disabled | loading

补充：

- 每屏最多一个 primary 主动作簇
- 具体组合以 13_component-variant-matrix.md 为准
- primary 默认承接当前页面 theme-main；secondary 和 ghost 优先维持中性骨架，只在边框、文字或 hover 轻底色中引入 theme-border 与 theme-strong
- disabled 必须回退到中性层，不继续保留高饱和主题色，避免误导用户认为动作可执行

### Navbar

用途：

- 承接顶部对象入口与全站快速入口

基本说明：

- 标题栏首先是全站一级导航，不承担正文内容展示，也不承担首页左侧内容入口侧轨的职责
- 它的基础功能分成三组：左侧品牌识别，中部对象入口，右侧工具入口
- 对象入口负责比赛、选手、战队等核心频道跳转；工具入口负责规则、我的、后台等辅助与操作页面跳转
- 它的目标是把全站主入口放稳、放清楚，而不是通过复杂装饰制造存在感

布局设计：

- 整体采用横向三段式结构：左品牌、中导航、右工具
- 三组内容保持在同一水平线上，并通过全宽容器与安全边距控制整体展开宽度
- 标题栏容器固定全宽，页面内容在其下方再决定采用首页全宽舞台还是 1240 版心
- 视觉上保持深色、轻边框、轻模糊和低强度激活态，让用户清楚当前所在位置，但不与页面主体争夺主视觉

规则：

- 左侧品牌，中部主导航，右侧搜索/我的/后台
- 移动端必须保留搜索和我的快速入口
- Navbar 容器始终全宽，不跟随页面版心收窄；页面内容在导航下方再决定是首页全宽还是 1240 版心
- 导航更适合抽取阵营徽章、石刻分隔线、金属底边，而不是复制游戏顶部 HUD 条
- 中部主导航只负责对象维，例如比赛 / 选手 / 战队，以及第二期扩展的社区 / 英雄
- 搜索 / 我的 / 后台固定归入右侧工具入口，不与中部对象入口混写成一组
- 杯赛范围切换不直接塞回 Navbar，而统一放到比赛、选手、战队页顶栏下方的胶囊二级导航
- Banner 不是 Navbar 的一部分，也不是标题栏本体；它只允许出现在二级导航下方
- 页面里所谓人物 Banner、战队 Banner、赛程 Banner 都只是同一个 Banner 槽位的内容变体，不是新的平级区块；同一首屏只允许 1 个 Banner
- Navbar 只使用全站基础色 N0 N1 N2 N6 N8；不要把 A5 B5 C5 这类主题主色直接铺到一级导航上
- 当前态优先通过字重、轻底色、短下划线和留白变化来表达，不做整块高饱和主色按钮

### Hero / PageIntro / DetailHero

用途：

- 展示页、频道页、详情页的题头与主叙事入口

何时使用：

- 页面需要建立对象认知与主 CTA 时

何时别用：

- Tab 内容区
- 后台列表正文区
- 阅读页正文段首

状态：

- neutral
- brand
- celebration

补充：

- celebration 只用于庆典型详情页或活动页
- 默认 action 数量不超过 2
- 统计信息优先 inline 或 4 项以内 grid
- 全站题头优先通过块面、圆角与直角的交叉、跨栏、边框和媒体窗建立对象感，而不是退回单层标题条
- 大标题可以更史诗，但摘要、时间、版本号、状态标签必须现代清楚
- 频道页题头如果跟二级主题联动，优先使用 theme-bg-soft、theme-border、theme-strong；不要把整页正文底色一起改成主题色

### SurfaceCard

用途：

- 标准信息卡、摘要卡、操作卡

规则：

- tone: default | muted | accent
- 同一列表内高度与底部操作保持统一
- 不承担多任务混合叙事
- 具体 density、emphasis、state 组合以 13_component-variant-matrix.md 为准
- 进入首页舞台、频道拼贴或专题拼贴时，可通过跨栏、内边距、色块背景和媒体比例形成大块面，不要求所有卡维持同尺寸
- hover 优先提供轻抬升、描边强化、局部高光或媒体遮罩滑动，不能引发父级重排
- 在详情页、阅读页、操作页、后台页中，SurfaceCard 也应作为大块面语义单元使用，例如“摘要块”“状态块”“风险块”“目录块”“回流块”
- 卡片上的装饰纹理、金属边和烟雾感只能做辅助，不能压过标题、标签、封面和数据
- 英雄、战队、赛事类卡片优先保证小尺寸下也能一眼认出对象，而不是追求整张插画完整

### Section Header / SectionIntro

用途：

- 组织一个内容段的标题、说明与操作

规则：

- 说明优先 1 到 2 句
- action 不超过一个主动作
- 在拼贴舞台中可作为大色块的标题内核，与卡片共面放置，不必总是独占一整行
- 标题可以有一点仪式感，但不能让整段说明都变成碑文式难读文案

### FAQ Accordion

用途：

- FAQ、单局列表、规则补充说明

规则：

- 标题直接表达问题
- 默认只展开当前项或有限多项
- 不承担页面级导航
- FAQ、攻略、规则正文优先是现代阅读体验，不做游戏面板拟态

### Form Field

用途：

- 登录、认领、后台编辑、筛选提交

必须状态：

- default
- focus-visible
- disabled
- error
- loading

规则：

- 字段错误与顶部摘要同时存在
- 危险操作确认不只依赖按钮颜色
- 表单页必须在 12_wireflow-and-state-spec.md 中定义 success、error、permission-denied 和 danger-confirmation
- 表单字段所在区域必须嵌入明确块面，不允许整页变成无边界长表单

### Table

用途：

- 后台高密度对比、批量处理

何时别用：

- 前台频道列表与详情展示

规则：

- 状态列使用 Badge
- 批量操作显示选中数量和退出入口
- 超过一屏的批量说明放入确认层
- Table 外层必须有块面壳层与工具条块，不让后台退回“裸表格贴满页面”

## 4. Pattern 库

### 首页三轨首屏

结构：

- 左侧 3 栏：热门比赛、热门选手、社区玩法、社区赞助等首页内容入口侧轨
- 中间 6 栏：内容主体与当前焦点
- 右侧 3 栏：登录引导“快来登录”或登录后个人信息

适用：

- 首页首屏

补充：

- 左栏是首页内容入口侧轨，不是第二条全站导航，也不是第二条内容流
- 中栏是唯一主内容区，承担首页最重的信息叙事
- 右栏只承担身份、登录和个人状态，不再和中栏争主视觉
- 三栏允许高低错位，但不要再使用切角；改用圆角主块配直角侧轨的交叉关系
- 首页首屏三轨使用全宽舞台，但必须遵守统一安全区和栅格，不做完全无约束漂浮块

### 频道页导航壳层

结构：

- Navbar
- 胶囊二级导航
- Banner
- 正文首块

适用：

- /matches
- /players
- /teams

补充：

- 这几层共同构成频道页首屏壳层，必须共享版心、边线、阴影家族和圆角逻辑
- 一级导航负责全站结构，视觉上更轻；二级导航负责范围识别，视觉上更准；Banner 负责主题补充，正文首块立即接住任务
- 二级导航按钮采用 community 风格的胶囊语法，默认先回到中性骨架，hover 和 active 再切入当前主题的浅底、浅边和强调色
- Banner 与正文的主题联动只作用于标题区、KPI、主按钮、标签和图表，不把正文阅读层整片染色

### 频道页主副栏

结构：

- PageIntro
- 工具条
- 8 + 4 或 3 + 9 主副栏

适用：

- 比赛、选手、战队、招募、新闻等频道页

补充：

- 频道页内容统一收在 1240 版心内，不和首页舞台使用同一宽度策略
- 当频道需要更强品牌舞台时，主副栏可以演化为非对称 Mosaic，但筛选、主列表、关系回流三类职责仍必须清晰可识别

### Mosaic Stage / 七巧板舞台

结构：

- 首页可全宽，其他页面为统一 1240 版心内舞台
- 3 到 6 个大色块按主次层级拼接
- 主块承载页面主叙事，次块承载证明、入口、状态或关系回流

适用：

- 首页首屏
- 频道页首屏
- 专题聚合页

规则：

- 只允许 1 个主块承担绝对主视觉
- 次块必须各自回答一个问题，例如“看什么”“去哪里”“为什么值得点开”
- 拼贴块之间必须通过色块、边框、圆角、直角收边或留白形成明确边界
- hover 反馈统一为轻抬升、遮罩滑动、描边变亮、角标推进中的 1 到 2 种，不混用过多动效语法
- 移动端必须回退为单列或双列顺序流，不能强保桌面拼贴关系
- 世界观味道优先通过材质、徽章、旗帜、符印和阵营感表达，不通过 HUD 元件堆砌表达
- 不把“有版心”理解成“只有一张大白板”；版心内仍要有强分区和层次
- 首页全宽不等于无约束；仍然必须服从安全边距、栅格、主次层级和响应式回退

### 阅读页偏置阅读流

结构：

- 9 + 3 或 3 + 9
- ReadingFlow 主体
- 轻关系侧栏或目录

适用：

- 新闻详情
- 公告详情
- 规则与指引

补充：

- 虽然正文宽度受控，但题头、目录、文末推荐、引用摘要仍要以不规则块面形成节奏，不要整页只剩一条纯正文柱
- 社区是“看内容”的，不是“看皮肤”的；装饰退后，标题、标签、摘要、版本号和对象名站前面

### 详情页 8 + 4 双栏

结构：

- DetailHero
- 左栏主体叙事
- 右栏关系与状态

适用：

- 比赛详情
- 选手详情
- 战队详情
- 招募详情
- 活动详情

补充：

- 左右栏不要求同高或同起线，允许通过跨栏摘要块、竖向关系块、横向回流块形成错位层级

### 后台列表页

结构：

- 标题区
- 工具条
- Table
- 批量操作层

适用：

- 所有后台列表页

补充：

- 后台仍沿用大色块母题，但只用于信息分区、风险提示和工具条层级，不做夸张品牌拼贴

### 后台编辑页

结构：

- FormSection
- 发布设置
- 关系选择器
- 审计与历史记录

适用：

- 选手、战队、比赛、赛季、新闻、活动等编辑页

补充：

- 表单、发布设置、关系选择器、审计记录、危险操作应拆成独立块面，而不是单张超长卡片

## 5. 组件变体与页面蓝图关系

- Page Brief 决定页面要完成什么
- Page Blueprint 决定区块怎么排
- Section Spec 决定区块怎么写
- Component Variant Matrix 决定组件怎么变

执行顺序：

1. 先确认页面类型和 Pattern
2. 再确认区块使用哪些组件
3. 最后在变体矩阵中选定合法组合

## 6. 使用与禁用总结

- 优先复用已有组件，不允许为单页效果新造组件名
- 不在列表页混用过多卡片高度和 CTA 命名
- 不在阅读页使用多重 Hero 或重复说明卡
- 不在后台复用前台庆典视觉和大面积品牌色
- 不把“有版心”理解成“退回模板站”；必须仍然服从栅格、安全边距、主次层级和响应式回退
