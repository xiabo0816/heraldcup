# 今晚就来社区 / Page Briefs: Home

分期说明：首页第一期以热门比赛、热门选手、社区玩法、社区赞助和身份入口为核心；社区摘要、最新新闻、内容拼贴和英雄相关入口均属于第二期增强。

## 1. 首页 /

### 页面目标

- 在前两屏内讲清楚这里既有比赛、人物、社区玩法和赞助支持，也有明确的身份入口
- 让游客知道为什么值得留下来
- 让已登录用户快速回到和自己相关的入口
- 在前两屏内建立平台气质、首页内容结构与身份入口认知
- 首页桌面端首屏固定为左 3 栏、中 6 栏、右 3 栏
- 首页继续继承顶部对象导航与顶部工具入口；首屏左 3 栏只承担首页内容入口侧轨，不与顶部导航重复分工

### 用户当前状态

- 游客：不知道平台是什么，不知道这里能看什么、做什么
- 已登录未成为选手用户：希望知道登录后能看到什么，并查看自己的 OpenDota 数据摘要
- 已成为选手用户：希望快速看到自己的 OpenDota 数据、参赛信息与个人入口

### 唯一主 CTA

- 默认主 CTA：查看比赛中心

次 CTA：

- 查看比赛详情或选手详情
- 继续认领或进入我的主页

### 必须出现的区块

首屏：

- 左栏内容入口侧轨：热门比赛、热门选手、社区玩法、社区赞助
- 中栏主体：顶部摘要与主 CTA，加下方热门比赛、热门选手、社区玩法、社区赞助 4 个连续模块
- 右栏身份：登录前展示“快来登录”和登录后可获得内容；登录后展示 OpenDota 数据；若已成为选手再展示参赛信息

后续屏：

- 无必选追加区块；首页核心内容收敛在首屏与中栏四模块内

第二期追加区块：

- 社区主线摘要
- 最热话题或最新新闻卡
- 社区意义拼贴画廊
- 英雄或内容型关系入口

### 不能出现的元素

- 传统居中 Hero + 三张功能卡的模板化首屏
- 八张同等级大卡同时争主视觉
- 假数据照片墙和无来源宣传图
- 第二个首页入口墙式筛选区

### 推荐结构顺序

游客态：

1. 左栏内容入口侧轨
2. 中栏内容主体：热门比赛 -> 热门选手 -> 社区玩法 -> 社区赞助
3. 右栏“快来登录”引导

登录态：

1. 左栏内容入口侧轨
2. 中栏内容主体：热门比赛 -> 热门选手 -> 社区玩法 -> 社区赞助
3. 右栏 OpenDota 数据与参赛信息

第二期可追加顺序：

1. 社区主线摘要插入游客态第 3 屏之后
2. 最热话题与最新新闻插入登录态第 5 屏之后
3. 社区意义拼贴画廊放在首页核心四模块之后，但不能早于一期主任务区

### 关键区块约束

- 首页第一屏只能有一个绝对主重块
- 第一期已登录态必须保证“我”和“比赛/个人关系”区优先于第二期内容
- 无战队、无比赛、无 OpenDota 时必须展示个人空状态
- 右栏登录前必须明确展示“快来登录”以及登录后可以看到的内容，不得只放一个空按钮
- 右栏登录后默认展示 OpenDota 数据摘要；如果该用户尚未成为选手，不展示参赛信息区块
- 右栏登录后且已成为选手时，必须在 OpenDota 数据之外追加展示参赛信息
- 首页热门比赛摘要区必须使用多条轮播，轮播项只展示比赛名称、时间、状态、结果等基础信息，不展示赛程表；赛程表仅能出现在赛程页的比赛详情中
- 首页热门比赛卡点击后必须进入比赛详情页，不允许在首页内展开完整赛程
- 首页热门选手摘要区必须使用多条轮播，轮播项只展示名称、Steam ID、擅长位置、擅长英雄、OpenDota 关键数据等摘要信息，不展示完整档案
- 首页热门选手卡点击后必须进入选手详情页，完整资料仅在选手详情页展示
- 社区玩法模块必须并列展示先锋杯、传奇杯、冠绝杯三档要求，三者视觉权重一致，不做主次排序
- 社区赞助模块必须展示核心作者“啵酱该吃饭了”，并同时展示其他多位赞助者头像与 ID
- 第二期社区与新闻模块不得挤压一期主舞台、身份入口和主打比赛的位置
- 左栏必须是稳定内容入口侧轨，不是临时资讯卡堆，也不冒充全站顶部导航
- 中栏必须保持唯一主内容区身份
- 右栏必须固定承担登录引导或登录后的个人数据，不得改成广告位或第二内容流

### 参考页面类型

- 展示页
- 登录态个性化门户
- 第一期赛事主舞台
- 第二期社区延展入口

## 2. 首页移动端规则

### 目标

- 重排任务顺序，不压缩桌面布局副本

### 必须保留

- 平台定位
- 主打比赛
- 主打选手
- 社区入口
- 社区赞助入口
- 身份入口
- 登录后 OpenDota 数据摘要

### 可以收敛的内容

- 词云与封神榜压缩为轻卡
- 合作方改横滑或双列
- 社区画廊减少装饰性密度
