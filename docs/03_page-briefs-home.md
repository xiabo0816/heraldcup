# Herald Cup 首页 / Page Briefs: Home

本文件只定义首页的任务、结构和禁止项。布局实例见 10_page-blueprint.md，区块硬约束见 11_section-specs.md，首页不参与对象页的胶囊二级导航。

## 1. 首页 /

### 速查表

| 项目 | 要求 |
| --- | --- |
| 页面目标 | 在前两屏内讲清 Herald Cup 是一个以开黑、周赛、固定队与互相照应为核心氛围的社区赛事门户，并把比赛、人物、战队和身份放回同一条主线 |
| 唯一主 CTA | 进入比赛中心 |
| 次 CTA | 查看人物档案、查看战队名册、进入我的主页 |
| 桌面端首屏 | 固定 3 + 6 + 3：左侧内容入口侧轨，中间内容主体，右侧身份轨 |
| 用户状态 | 游客、已登录未成为选手、已成为选手 |
| 第一性约束 | 首页继承顶部对象入口与顶部工具入口，但不复用对象页胶囊二级导航 |

### 必须区块

- 左栏内容入口侧轨：比赛中心、人物档案、战队名册、怎么上场；它们只保留为 4 个更窄的简单按钮，点击后滚动到首页中栏对应模块，页面下滚后左栏继续固定在视口内；不再额外包一层重复外框
- 中栏内容主体：中部固定为五张顺排卡片，先用独立的平台定位卡讲清主线与主 CTA，后接比赛中心、人物档案、战队名册、身份链路四张连续模块卡；五张卡在桌面端和移动端都按一行一个的纵向顺序展开
- 右栏身份轨：固定拆成 4 个从上到下平铺的模块，每行 1 个模块；桌面端随页面滚动时右栏继续固定在视口内，只让中栏主轴继续滚动；登录前显示身份提示、浏览提示、链路提示与登录动作，登录后显示账号、认领、队伍与邀请、主动作四段
- Footer：品牌、对象频道入口、工具与社区文化入口、版权信息

### 禁止项

- 传统居中 Hero + 三张功能卡首屏
- 八张同等级大卡同时争主视觉
- 假数据照片墙、无来源宣传图、广告位式右栏
- 第二个首页入口墙式筛选区
- 在首页题头或中栏顶部复制比赛、选手、战队专属的胶囊二级导航

### 顺序与权重

- 游客态顺序固定为左栏入口侧轨 -> 中栏五卡主轴 -> 右栏登录引导；桌面端保持左右侧轨固定，只滚动中栏主轴
- 登录态顺序固定为左栏入口侧轨 -> 中栏五卡主轴 -> 右栏身份进度与邀请摘要；桌面端保持左右侧轨固定，只滚动中栏主轴
- 首页第一屏只能有一个绝对主重块，中栏始终是唯一主内容区
- 第二期增强内容只能排在一期主任务之后，不能挤占比赛、人物、战队和身份入口

### 硬约束

- 左栏四个入口必须是首页内目录式锚点，只负责跳到中栏对应模块，表现为 4 个更窄的简单按钮，不能伪装成四个独立频道页入口或扩成说明卡列表，也不能再包一层重复外框
- 比赛中心模块必须展示当前赛季、对阵双方、状态和结果摘要，点击后进入比赛详情页，不能在首页内展开完整赛程表
- 人物档案模块必须展示人物名称、当前位置、当前归属与代表比赛摘要，点击后进入人物详情页，不展示完整档案
- 战队名册模块必须展示战队名称、当前杯赛归属、近期成绩或简介，点击后进入战队详情页，不展示完整阵容表
- “怎么上场”模块必须讲清登录、认领、建队与邀请的前后关系，并给到明确动作入口
- 右栏默认讲身份进度，不允许用 OpenDota 数据替代身份主线；如需显示数据摘要，也只能作为补充信息；四个模块必须纵向平铺，不能再包成单一大卡片
- 无战队、无比赛、无认领状态时必须有明确空状态和下一步入口

### 首页材质补充

- 首页平台定位卡文案必须先讲清社区气质：这里不是冷冰冰的赛事聚合页，而是以微信群、Kook 语音、每周固定对黑和娱乐杯赛串起来的社区入口；语气要欢迎新手、固定队和围观玩家，同时明确“玩得开心、互相理解、别恶意压力”是默认文化
- 首页文案允许点到社区日常，例如每周三晚对黑、每周五晚比赛、随时接龙开黑、固定队建公会与公共语音入口，但表达必须服务首页导览，不把首页写成整页群公告
- 首页任何文化表达都不能削弱主 CTA 与四条主线入口；社区氛围是解释这些入口为什么值得继续走，不是替代比赛、人物、战队和身份模块本身
- 首页用户文案必须像对真实玩家说话，而不是像产品说明或开发需求：少用“链路”“收口”“主线”“入口”这类内部词，多用“先看看这周打什么”“想下场怎么开始”“第一次来也没关系”这类用户能直接接住的话
- 首页文案要同时满足两件事：有亲和力，让第一次来的人敢继续看；有底线，让人知道这里欢迎一起玩，但不欢迎恶意压力、恶意吵架和越界消耗
- 首页四个主模块的卡片摘要和空态也必须保持同一口气：像在告诉玩家“这里能看到什么、现在没内容时该怎么办”，不要退回“查看详情”“暂无简介”“准备完成后显示”这类站内占位句
- 比赛、人物、战队模块在没有合适摘要时，默认文案要分别回答“这一局值不值得点进去”“这个人平时打什么、跟谁玩”“这支队平时是什么气质”；没有数据时则要给出轻量解释和等待路径
- “怎么上场”模块的默认条目不能再写成后台流程说明；即便是登录前，也要像在带新玩家入门，告诉他先做什么、做完会看到什么

- 中栏主舞台必须是首页唯一最强材质块：可使用阵营光带、遗迹雾面和低噪点纹理，但不允许退回传统纯色 Hero 或满屏宣传图
- 左栏入口侧轨与右栏身份轨必须比中栏更克制，优先表现为稳定石板块面；它们可以有轻微主题提亮，但不允许复制中栏主舞台的强光带和大面积渐变
- 中栏平台定位卡与后续四个连续模块卡应组成同一条五卡主线，按单列纵向顺排；平台定位卡单独成块，不再把后面四张模块卡包进同一外层大卡；五张卡需要共享同一家族的边线、底色和轻纹理来源
- 主舞台中的统计块和主 CTA 可以承接高光色，但高光只承担点亮作用，不允许把统计区做成金色大底或强饱和彩带
- 首页所有材质和纹理都必须服务“平台定位 -> 比赛 -> 人物 -> 战队 -> 身份”的阅读主线；如果装饰影响识别顺序，优先删装饰
- 首页的页面基础层必须完整跟随 Radiant 或 Dire，不允许把先锋杯、传奇杯、冠绝杯三色抬成首页主背景
- 若首页需要表达当前赛季或专题入口，只允许在对应模块局部使用杯赛色做标签、短条带、入口卡或专题 CTA；主 CTA 仍默认跟随当前主题的 `--primary`
- Radiant 首页应表现为自然、明亮、生命感；Dire 首页应表现为冷峻、压迫、硬核感，但两者都要先把比赛、人物、战队、身份四条主线讲清

### 第二期追加边界

- 允许追加社区主线摘要、最热话题或最新新闻卡、社区意义拼贴、英雄或内容型关系入口
- 追加位置必须晚于首页核心四模块
- 第二期内容不能替代首页第一期的比赛、人物、战队和身份主线

## 2. 首页移动端规则

### 必须保留

- 平台定位
- 比赛中心
- 人物档案
- 战队名册
- 身份链路
- 身份入口
- 登录后身份进度摘要

### 可收敛内容

- 比赛、人物、战队卡片改为单列轻卡
- 身份链路压缩为 2 到 3 条关键步骤
- 统计块改为双列或横滑

### 移动端底线

- 只允许重排任务顺序，不允许压缩桌面副本
- 顺序固定为内容入口 -> 主体内容 -> 身份入口 -> Footer
- Footer 仍然只承担收束和回流，不承担主 CTA 与范围切换
