# 今晚就来社区 / Information Architecture

## 1. IA 原则

- 第一期稳定主线是比赛、选手、战队、我的
- 第一期开赛相关页面统一采用双轴矩阵：顶部对象入口负责对象维，页面级范围条负责杯赛维
- 第二期扩展主线统一收口到 14_phase-two-extension.md
- “我的”是身份和操作入口，不与公开人物详情混同
- 后台只承担维护、审核、发布和高风险变更，不承担品牌叙事
- 首页左侧 3 栏只承担内容入口侧轨，不参与第一层导航定义

## 2. 顶部导航分层

第一期固定顶栏对象导航：

- 品牌 Logo 返回首页
- 比赛
- 选手
- 战队

第一期固定顶栏工具入口：

- 搜索
- 我的
- 后台

第一期统一页面级范围条：

- 全站竞技对象页面统一使用：全部 / 先锋杯 / 传奇杯 / 冠绝杯
- “全部”表示全站对象视图，“先锋杯 / 传奇杯 / 冠绝杯”表示当前杯赛范围或资格池视图
- 页面级范围条就是比赛、选手、战队频道页的二级导航，不替代顶栏对象导航；它负责切换当前对象所在的杯赛上下文，本体是一条紧贴顶部导航的简单范围导航条
- 比赛、选手、战队三个频道页的首屏固定顺序是“顶部导航 -> 二级导航（页面级范围条） -> 条件性 Banner（仅具体杯赛态） -> 主工作台或主目录”
- 用户在比赛 / 选手 / 战队三个对象频道之间横向切换时，默认保留当前范围
- 我的、搜索、后台不参与双轴矩阵；它们属于工具轴，不保留当前范围语义

第二期顶部对象入口扩展统一见 14_phase-two-extension.md。

导航层级定义：

- 双轴矩阵不是额外露出的一个导航栏目，而是第一期导航的组织原则：对象入口承载横轴，页面级范围条承载纵轴
- 顶栏对象导航 = 第一层，只负责“我现在看什么对象”
- 顶栏工具入口 = 并列工具层，只负责搜索、身份和管理入口
- 页面级范围条 = 页面级第二层 = 二级导航，只负责“我当前看的是全站还是哪个杯赛范围”，并承担双轴矩阵纵轴的页面表达
- 页面正文 = 第三层，只展示当前对象在当前范围下的内容

设计表达：

- 双轴矩阵只在 /matches、/players、/teams 三个对象频道中成立；首页、阅读页、操作页、后台页不参与
- 页面中必须同时存在“顶部对象入口”和“页面级范围条”，两者不能混成一排，也不能共用同一个当前态样式
- 页面级范围条不是装饰标签，也不是普通 segmented control；当前范围应同步体现在页面标题、摘要、统计、列表标题或右侧关系卡中
- 用户在比赛、选手、战队三个对象频道之间横向切换时，默认保留当前范围，以维持对象维与范围维的连续性
- 页面级范围条、正文和侧栏共同表达当前范围，不把范围维设计成脱离内容的孤立标签行
- 页面级范围条固定采用“简单二级导航条”语法：宽度与顶部导航一致，高度与顶部导航接近，紧贴顶部导航栏；内部仅保留全部 / 先锋杯 / 传奇杯 / 冠绝杯 4 个范围入口；“全部”态不出 Banner，具体杯赛态才在二级导航下方出现对应 Banner

### 双轴矩阵定义

横轴 = 对象维；纵轴 = 杯赛范围维。第一期公开对象页统一落在以下矩阵中：

| 范围 \ 对象 | 比赛 | 选手 | 战队 |
| --- | --- | --- | --- |
| 全部 | 全站比赛总览 /matches | 全站选手目录 /players | 全站战队目录 /teams |
| 先锋杯 | 先锋杯比赛工作台 /matches?scope=pioneer | 先锋杯选手池 /players?scope=pioneer | 先锋杯战队池 /teams?scope=pioneer |
| 传奇杯 | 传奇杯比赛工作台 /matches?scope=legend | 传奇杯选手池 /players?scope=legend | 传奇杯战队池 /teams?scope=legend |
| 冠绝杯 | 冠绝杯比赛工作台 /matches?scope=crown | 冠绝杯选手池 /players?scope=crown | 冠绝杯战队池 /teams?scope=crown |

矩阵解释：

- 横向切换表示“我仍处在同一个范围里，但改看另一个对象”
- 纵向切换表示“我仍在看同一个对象，但切到另一个杯赛范围”
- 任一交叉点都不是新页面类型，而是“同一对象频道在不同范围态下的视图”
- 我的、搜索、后台位于矩阵外侧，属于工具与操作体系，不进入这个公开对象矩阵

矩阵展示语法：

- 顶部第一层固定为对象入口：比赛 / 选手 / 战队；它只回答“当前对象是什么”
- 顶部第二层固定为页面级范围条，也就是二级导航：全部 / 先锋杯 / 传奇杯 / 冠绝杯；它直接位于顶部对象导航下方
- 条件性 Banner 只允许出现在二级导航下方、主工作台或主目录上方；不能插到顶部导航与二级导航之间，也不能提到二级导航上方
- 范围导航条内部固定为 4 个等宽切换按钮，顺序固定为全部 / 先锋杯 / 传奇杯 / 冠绝杯
- 当前范围切换后，至少同步改变主列表标题、页面说明、统计数字、资格 Badge、右侧关系卡标题中的 2 项以上
- “全部”态时，二级导航下方直接进入主工作台或主目录，不插 Banner；切换到具体杯赛态时，才允许在二级导航下方插入 1 个对应 Banner
- 二级导航的底边必须直接进入主工作台或主目录区，不在中间插入第二个 Hero 或说明条
- 右侧侧栏第一张卡固定复述当前范围语义，形成“二级导航 + 右栏范围说明”的双点锚定
- 页面级范围条中的 4 个入口等宽、等高；当前态通过更高饱和度、描边与阴影提升，而不是通过尺寸放大打破齐线

## 3. 二级结构

### 比赛（第一期）

解决的问题：

- 当前品牌下有什么比赛、选手、队伍
- 赛季结构、参赛对象和当前可执行动作是什么
- 这场比赛、这名选手、这支队伍与整个赛季主线的关系是什么
- 用户当前处于普通用户、选手还是队长，以及在该上下文里能做什么

二级层级：

- 比赛总览 /matches
- 赛季详情 /matches/seasons/[slug]
- 赛季结算 /matches/seasons/[slug]/final
- 比赛详情 /matches/[slug]

比赛总览 /matches 的页内结构：

- 页面级范围条：全部 / 先锋杯 / 传奇杯 / 冠绝杯
- 左侧 8 栏主工作台：当前范围内的赛程、赛季、阶段与结果
- 右侧 4 栏信息侧栏：显示当前范围说明、用户身份、当前杯赛资格状态与进入其他对象频道的入口
- /matches 只负责“比赛对象”本身，不再在同页承担选手和战队目录

### 战队（第一期）

解决的问题：

- 社区里有哪些队伍
- 每支队伍的阵容、荣誉和当前状态是什么
- 是否在招募、该去哪里继续了解
- 已成为选手后如何建立队伍、邀请队员、管理队伍

二级层级：

- 战队列表 /teams
- 战队详情 /teams/[slug]

战队频道边界：

- /teams 仍是展示页，但承担“战队对象 + 杯赛范围”目录职责
- 页面级范围条统一切换全部 / 先锋杯 / 传奇杯 / 冠绝杯
- 当前范围为“全部”时展示全站战队目录；切到某杯时展示该杯战队池
- 建队、邀请队员、邀请训练赛、解散队伍等操作从展示页右栏动作或弹层进入，不把展示页改成后台工作台

### 选手（第一期）

解决的问题：

- 有哪些人物值得看
- 选手与战队、比赛的关系是什么
- 我与这些人之间有什么关系
- 普通用户如何申请成为选手，队长如何邀请该选手入队

二级层级：

- 选手列表 /players
- 选手详情 /players/[slug]

选手频道边界：

- /players 仍是展示页，但承担“选手对象 + 杯赛范围”目录职责
- 页面级范围条统一切换全部 / 先锋杯 / 传奇杯 / 冠绝杯
- 当前范围为“全部”时展示全站选手目录；切到某杯时展示该杯选手池
- 成为选手、建立队伍、邀请入队等动作通过详情页或右栏动作进入弹层页，不把频道页改成表单页

### 第二期扩展

- 社区、新闻、活动、话题、招募、英雄与第二期后台模块统一见 14_phase-two-extension.md

### 我的（第一期）

解决的问题：

- 我是谁
- 我当前的身份状态和操作能力是什么
- 我的申请、认领、队伍管理做到哪里了
- 我收到了哪些组队邀请或训练赛邀请

二级层级：

- 我的主页 /my
- 认领历史 /my/claims
- 队伍管理 /my/team
- 邀请收件箱 /my/invitations
- 登录页 /login

### 后台（分期交付）

解决的问题：

- 审核谁、发布什么、回滚什么、风险在哪里

二级层级：

- 后台首页 /admin
- 认领审核 /admin/claims, /admin/claims/[id]
- 选手 /admin/players
- 战队 /admin/teams
- 比赛 /admin/matches
- 赛季 /admin/seasons
- 赛事 /admin/tournaments
- 第二期后台模块统一见 14_phase-two-extension.md

## 4. 命名原则

- 一级栏目使用用户自然语言，不使用内部数据模型术语
- 第二期命名与归属统一见 14_phase-two-extension.md
- 页面标题优先回答对象和任务，例如“比赛中心”“战队荣誉”“选手名册”
- CTA 命名使用动作词，不用情绪词或营销词替代语义

## 5. 查找效率要求

第一期必须在 2 到 3 次点击内找到：

- 当前赛季与主推比赛
- 登录、认领、我的主页
- 规则与新手指引
- 后台入口与审核列表

第二期查找效率要求统一见 14_phase-two-extension.md。

## 6. 回流关系

- 第一期：比赛详情回流到赛季、战队、选手
- 第一期：选手详情回流到战队、比赛、OpenDota，并在队长态提供邀请入队动作
- 第一期：战队详情回流到阵容、代表比赛，并在队长态提供邀请训练赛动作
- 第一期：比赛、选手、战队三个对象频道统一共享“全部 / 先锋杯 / 传奇杯 / 冠绝杯”页面级范围条，并在各自频道内切换当前范围
- 第一期：普通用户可从赛程或选手上下文进入“申请成为选手”；已是选手用户可进入“建立队伍”；队长可进入“解散队伍”
- 第二期关系回流统一见 14_phase-two-extension.md

## 7. 信息优先级底线

- 展示页先讲平台与归属，再导向动作
- 频道页先让人找到对象，再讲故事
- 阅读页先读清正文，再给关系回流
- 操作页先完成任务，再补充扩展入口
- 后台页先判断状态和风险，再执行变更
