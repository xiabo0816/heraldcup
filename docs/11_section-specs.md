# 今晚就来社区 / Section Specs

## 1. 这份文档解决什么问题

- Page Blueprint 定义页面怎么排
- Section Spec 定义单个区块怎么写、怎么复用、怎么限制 AI 自由发挥

结论：

- AI 生成页面时，不是在“设计一个区块”
- AI 只是在“填一个已经定义好的区块规格表”

## 2. 每个 Section Spec 的必填字段

- 区块名称
- 区块用途
- 布局模式
- 栅格占比
- 形状定义
- 拼接关系
- 内容槽位
- 允许组件
- 允许组件变体
- 禁止项
- 响应式规则
- Promptframe 约束

推荐表头：

| 字段 | 内容 |
| --- | --- |
| 区块名称 | Feature Grid |
| 用途 | 解释 3 个核心卖点 |
| 布局 | 左标题右 3 卡 / 12 或 14 栏中的 4 + 10 |
| 形状定义 | 左侧纵向高柱块，右侧 3 个横向短块，右上块保留直角收边 |
| 拼接关系 | 左柱与右上块顶对齐；右上块压住右下两块 1 档；块与块之间保留 1 条连续 gutter |
| 内容槽位 | 标题 1 行、描述 2-3 行、图标 1 个、CTA 0-1 个 |
| 允许组件 | SectionIntro / SurfaceCard |
| 允许变体 | SurfaceCard.tone=default 或 accent |
| 禁止 | 不要轮播，不要超过 3 列 |
| 响应式 | lg 3 列、md 2 列、xs 1 列 |

## 3. 通用 Section 类型

全站块面总规则：

- 所有页面都应让用户感知到大块面分区，而不是只有首页才有设计感
- 不规则不是随机；每个块面的尺寸、位置和颜色都要能解释其信息优先级
- 阅读、操作、后台页可以降低造型强度，但不能丢掉块面语言
- 每个区块必须定义自身形状和与周围区块的拼接逻辑，不能只定义“占 8 栏”
- 拼接关系至少写清：与上一区块的垂直关系、与同层邻块的水平关系、是否存在压边/咬边/错位/留缝

### Hero / PageIntro

- 用途：建立页面对象认知、交代当前状态、承接唯一主 CTA
- 布局：整宽或 8 + 4
- 形状定义：整宽舞台块或左右双块咬合舞台，主块偏圆角，侧块可保留直角或单侧圆角
- 拼接关系：下一区块必须贴着主舞台的某一边进入，不能完全脱离成第二个独立舞台
- 内容槽位：eyebrow 1 行、标题 1-2 行、描述 2-4 行、CTA 1 主 1 次、数据 0-4 项
- 允许组件：PageIntro / DetailHero / Badge / Button
- 禁止：第二个平级 Hero、轮播、过多徽章墙
- 补充：若 Hero / PageIntro 出现在 /matches、/players、/teams 的二级导航下方且当前范围为具体杯赛态，则其背景、描边、强调标题和 CTA 必须挂接当前主题壳层
- 响应式：移动端 CTA 纵向堆叠，副信息下沉到正文前

### Mosaic Stage

- 用途：在首页无版心或其他页面有固定版心的舞台页中，用七巧板式大色块同时承接主叙事、证明和入口
- 布局：流体 14 栏，多块跨栏拼接，可用 6 + 8 / 4 + 4 + 6 / 3 + 4 + 7 等非对称组合
- 形状定义：由 3 到 6 个异形大块组成，至少包含 1 个横向主块、1 个纵向附块和 1 个错位连接块
- 拼接关系：主块必须与至少两个辅助块共享边或形成咬边；相邻块之间只能使用连续 gutter、半阶压边或直角对锁这三类关系
- 内容槽位：主标题 1 组，主摘要 1 组，主 CTA 1 个，辅助 CTA 0-2 个，证明块 1-2 个，关系或状态块 1-3 个
- 允许组件：PageIntro / SectionIntro / SurfaceCard / Badge / Button
- 禁止：所有块同尺寸同权重；为了造型打乱阅读顺序；hover 触发整体重排
- 约束补充：首页块面必须落在安全区内，其他页面块面必须落在页面版心内，不允许无约束漂浮
- 响应式：md 允许 2 列回排；xs 回到单列顺序流，顺序必须仍是主块 -> 证明块 -> 入口块 -> 辅助块

### Featured Strip

- 用途：在主舞台后立即提供证明或焦点入口
- 布局：1 大 2 小、4 卡横排或双列拼接
- 形状定义：横向长条主块 + 侧挂短块，或 4 个同语法短块组成折线带
- 拼接关系：与上方舞台保持 1 条连续边界线；内部块之间允许首尾错半档，但不能完全脱节
- 内容槽位：标题、摘要、状态、1 个 CTA
- 允许组件：SurfaceCard / MatchCard / PlayerCard / TeamCard / ContentCard
- 禁止：把 Featured Strip 做成第二个 Hero

### Filter Toolbar

- 用途：缩小范围、排序、切换视图
- 布局：横向工具条或 3 + 9 Sticky 侧筛
- 形状定义：横向薄条块、纵向筛选柱块或嵌入主列表顶部的内凹条块
- 拼接关系：必须明确附着在主列表上缘或侧缘，不能悬空成独立海报块
- 内容槽位：搜索、筛选、排序、计数、清空
- 允许组件：Form Field / Tabs / Sheet / Badge
- 禁止：过多筛选造成二屏前无法浏览内容
- 补充：频道页处于具体杯赛态时，Filter Toolbar 的外层底、描边、当前筛选项和计数提示都必须跟随当前主题壳层，不保留上一范围颜色
- 响应式：复杂筛选进入 Sheet

### Card Grid

- 用途：承接可浏览对象列表
- 布局：2-4 列网格或单列大卡流
- 形状定义：规则网格块、预定义高低差 Mosaic 网格块或单列长条块流
- 拼接关系：同一组卡片只允许使用 1 套错位规则；必须写清首列、末列和上下行的对齐关系
- 内容槽位：封面、标题、摘要、meta、状态、CTA
- 允许组件：SurfaceCard 及业务卡片
- 禁止：同一列表混入多种高度策略
- 补充：在 /matches、/players、/teams 的具体杯赛态中，Card Grid 的组边界、分区标题、选中态和列表外壳应统一切入当前主题壳层；卡内长文本保持中性色文字体系
- 响应式：展示型 Mosaic 列表可在桌面端允许 2 到 3 种预定义高度，但必须成组重复，不能随机错位

### Reading Flow

- 用途：承接正文、规则、说明、长阅读
- 布局：9 + 3 或 3 + 9
- 形状定义：正文主柱 + 侧挂目录块，或顶部摘要块 + 正文长柱 + 文末回流块
- 拼接关系：正文块始终是主轴；目录、引用、推荐块只能贴边或顺延，不得切断正文主轴
- 内容槽位：标题层级、正文、插图、引用、目录、关系卡
- 允许组件：ReadingFlow / SectionIntro / Accordion
- 禁止：拼贴式视觉干扰正文
- 响应式：正文始终保持可读宽度，题头块、目录块、引用块和文末回流块可以保留不规则边界

### Detail Summary Aside

- 用途：放状态、关系、快捷动作、轻统计
- 布局：8 + 4 的右栏
- 形状定义：纵向堆叠短柱块，允许顶部做包角或底部做直角收束
- 拼接关系：与主内容共享顶线或中段锚点，不允许从视觉上漂浮成无关栏位；在 8 + 4 频道页与详情页中，桌面端优先作为固定右侧轨存在，左侧主区滚动
- 内容槽位：状态标签、简短说明、轻动作、相关对象
- 允许组件：SurfaceCard / Badge / Button / Tabs
- 禁止：右栏塞入第二条完整内容流
- 补充：若右栏位于对象频道的具体杯赛态中，整组卡堆的底色、描边、标题强调和主次按钮必须统一挂接当前主题壳层
- 响应式：桌面端优先纵向块面堆叠并保持固定侧轨，移动端回到主内容后的顺序块面，不保留悬空侧贴样式

### FAQ Accordion

- 用途：回答真实问题，减少流程阻力
- 布局：单栏或 8 + 4 主栏内嵌
- 形状定义：单列层叠块或嵌入主块的内凹列表块
- 拼接关系：必须附着在正文或主内容块中，不单独起一套主舞台边界
- 内容槽位：问题、回答、补充链接
- 允许组件：Accordion / SectionIntro
- 禁止：把 FAQ 当目录或规则正文替代品

### CTA Band

- 用途：在尾部收束页面任务
- 布局：整宽带状或双列收束
- 形状定义：尾部横向收束带、折线带或双块对锁收束块
- 拼接关系：与上一块通过连续底边或直角反向收边收束，不得像新页面开头一样重新起势
- 内容槽位：标题、说明、1 个主 CTA、0-1 个次 CTA
- 允许组件：SectionIntro / Button / SurfaceCard
- 禁止：尾部再重新讲一遍整页内容
- 补充：频道页回流或尾部 CTA 如果位于二级导航以下，应跟随当前范围主题切换；“全部”态再退回中性收束带

### Banner

- 用途：仅在具体杯赛态承接当前范围的摘要、焦点对象或轻说明
- 布局：整宽轻 Banner 或 8 + 4 轻拼接
- 形状定义：横向摘要块、轻双块拼接或单块焦点带；视觉强度低于首页 Hero
- 拼接关系：必须紧贴胶囊二级导航底边，并位于主工作台或主目录上方；只允许出现在 pioneer / legend / crown；消失后由主工作台直接上提顶替其位置
- 内容槽位：杯赛名 1 行、摘要 1 组、焦点入口 1 个、统计 0-2 项
- 允许组件：SurfaceCard / Badge / Link / Button
- 允许变体：SurfaceCard.tone=accent|default；Badge.tone=pioneer|legend|crown
- 禁止：在“全部”态出现；跑到二级导航上方；变成第二套导航；做成首页主 Hero；同时展示多个平级 Banner
- 补充：频道页首屏只有这 1 个 Banner 槽位；如果此处已经承接人物推荐、战队推荐或赛程焦点，正文首块不得再新增第二个 Banner
- 一体化要求：Banner 必须被看作频道页首屏连续壳层的中段，不是独立营销横幅；它要与上方二级导航共享版心、与下方正文首块共享进入线
- 色面要求：Banner 的背景只允许使用当前范围主色的低一档渐变、雾面或轻纹理，不得额外引入跨范围的新主色；亮度峰值低于顶部导航主识别和正文主 CTA
- 几何要求：若 Banner 为整宽轻带，则外侧边线与下方正文首块保持同一外轮廓；若 Banner 为 8 + 4 轻拼接，则左块与主工作台、右块与右栏首卡必须沿同一竖向控制线延续
- 主题要求：Banner 不是唯一的主题承载物；一旦 Banner 出现，其下方正文首块、工具条、主列表、右栏和回流区也必须沿同一主题壳层继续展开
- 响应式：xs 单列轻摘要块，仍保持紧贴二级导航

线框顺序：

```text
标题栏
-> 胶囊二级导航
-> [仅某杯态] Banner
-> 主工作台 / 主目录
```

### Global Footer

- 用途：在全站页底稳定收束品牌、导航回流、规则入口与版权信息
- 布局：3 列或 4 列信息组 + 底部版权带
- 形状定义：上方信息组收束带 + 下方薄版权带；整体偏直角或单侧小圆角
- 拼接关系：只能从页面最后一个正文块的底边收口，不得像新页面开头一样重新起第二主舞台
- 内容槽位：品牌说明 1 组、对象频道入口 1 组、工具/规则入口 1 组、版权/署名 1 组
- 允许组件：SectionIntro / Link / SurfaceCard / Badge
- 禁止：主 CTA、大色块营销 Banner、杯赛二级导航、赛事统计、热区摘要
- 响应式：lg 3 到 4 列；xs 单列堆叠，版权带始终在最底部

### Admin Table Region

- 用途：后台批量浏览、筛选、处理
- 布局：标题区 + 工具条 + Table
- 形状定义：上工具条块 + 下主表格块的双层工作台，必要时侧挂风险短块
- 拼接关系：工具条必须压住或贴住表格上沿；风险块只能挂侧或贴底，不能插进主表格中央
- 内容槽位：统计、筛选、批量操作、表头、空态、分页
- 允许组件：Table / Badge / Dialog / Form Field
- 禁止：只靠整行染色表达状态
- 响应式：xs 表格可退化为卡片列表，但必须保留工具条块、筛选块和批量状态块

### Reading Header Block

- 用途：在阅读型页面用克制的大块面承接标题、摘要、meta 与目录入口
- 布局：整宽块或 9 + 3 偏置块
- 形状定义：横向题头块，可用一侧圆角和一侧直角的交叉边界，用来接正文主柱
- 拼接关系：正文必须从题头底边自然接出，不能在中间断出大空白
- 内容槽位：标题 1 组，摘要 1 组，meta 1 组，目录或关系入口 0-1 组
- 允许组件：PageIntro / SectionIntro / SurfaceCard / Badge
- 禁止：做成庆典 Hero；把阅读页头图做成压过正文的海报墙
- 响应式：xs 保留标题和摘要块，目录下沉到正文前或文末

### Admin Workbench Mosaic

- 用途：在后台用克制的大块面组织指标、工具条、主工作区、风险区和审计区
- 布局：4 + 8、3 + 9 或 6 + 6，允许局部错位
- 形状定义：主工作台横块 + 侧列信息块 + 底部审计或风险块
- 拼接关系：主工作台必须作为最大连续块；风险块和审计块只能贴边、挂角或底部顺延，不能切碎主工作区
- 内容槽位：指标 2-4 项，工具条 1 组，主工作区 1 组，风险提示 0-1 组，审计信息 0-1 组
- 允许组件：SurfaceCard / Table / Form Field / Badge / Dialog
- 禁止：后台区块做成首页式高饱和拼贴；主工作区和危险操作混在同一块面
- 响应式：md 起允许上下堆叠；xs 风险区必须紧贴主工作区之后

## 6. 区块验收清单

- 是否写清楚了布局而不是只写内容主题
- 是否写清楚了区块是什么形状，而不是只写“卡片/区域/模块”
- 是否写清楚了与上下左右区块如何拼接，而不是只写“放在旁边”
- 是否限制了列数、长度和组件范围
- 是否写明禁止项
- 是否给出移动端折叠、换列、抽屉规则
- 是否说明这个区块是复用型还是页面专属型

### 7.1 Banner（选手变体）

| 字段 | 内容 |
| --- | --- |
| 区块名称 | Banner（选手变体） |
| 用途 | 在选手频道首屏建立单一人物印象，再把用户送进筛选与人物关系流 |
| 布局 | 8 + 4，左侧频道说明与统计，右侧推荐人物卡 |
| 栅格占比 | lg 8 + 4；md 单列；xs 单列 |
| 形状定义 | 左侧横向信息大块，右侧纵向人物高卡，右卡顶部保留直角、主体用圆角 |
| 拼接关系 | 左块与右卡共用顶线；右卡下缘低于左块形成半档落差；下一区块从左块底边起接 |
| 内容槽位 | 频道标题 1 行，说明 2-3 行，统计 3 项，推荐人物 1 位，打法标签 2-4 个，英雄 Chip 2-4 个，CTA 1-2 个 |
| 允许组件 | SurfaceCard / PlayerAvatar / HeroChip / Button |
| 允许变体 | SurfaceCard.tone=accent；HeroChip.size=sm；Button.primary=md |
| 禁止 | 多位推荐人物平级并列；用轮播切人物；顶部筛选条抢主视觉 |
| 响应式 | xs 统计卡纵向堆叠，推荐人物卡下沉到频道说明之后 |

```text
区块名称：Banner（选手变体）
区块用途：用一个人物说明当前杯赛范围下的选手池值得点开；它就是选手页首屏唯一 Banner
形状定义：左宽右高的双块拼接，人物卡是右侧竖向高块
拼接关系：左块和右卡顶对齐，下一区块从左块底边顺接，不要让人物卡孤立漂浮
```

### 7.1A Home Hero Mosaic

| 字段 | 内容 |
| --- | --- |

层级原则：

- 顶部导航是主导航，胶囊二级导航是次导航；两者必须连续，但不能等权
- 胶囊二级导航必须看起来像顶部导航的下一级，而不是独立新舞台
- 当前态按钮是二级导航里的唯一主重点；其余按钮与整条导航都应服务于衬托当前态，而不是整体一起变重
- 胶囊二级导航要与下方 Banner 或正文首块共同组成一个连续首屏系统；它不能只在顶部自成一条孤立横条

尺寸与样式参数：

- 整体：共享频道主区 1240 版心；单按钮高度建议 36 到 44；xs 为 32 到 40
- 内边距：按钮内边距遵循胶囊按钮骨架，导航行本身不额外包壳层
- 结构：4 个按钮按文案自适应宽度，使用稳定 gap 排列；xs 端允许换行
- 圆角：按钮圆角 radius.xl；整行导航不再保留整条直线外框
- 描边：单按钮描边 1px border.default；当前态按钮描边 1px border.emphasis；不再使用按钮之间的内分隔线
- 阴影：当前态按钮 0 10 24 rgba(0,0,0,0.18)；非当前态按钮无阴影
- 按钮尺寸：lg 高 40 到 44；md 高 36 到 40；xs 高 32 到 40
- 按钮内容：标题 1 行 + 可选短标签 1 行；不允许第三行说明
- 颜色：全部 #2E3442 -> #4B4439；先锋杯 #236D5C -> #266088；传奇杯 #563880 -> #B08144；冠绝杯 #853454 -> #8A4D2E

补充规则：

- 二级导航必须固定在频道主区顶部，不能回退成整条贴顶范围带或悬浮为第二张卡
- 页面首屏层级固定为顶部导航 -> 胶囊二级导航 -> Banner（仅某杯态，可选） -> 主工作台或主目录
- “全部”按钮固定使用中性色；先锋杯、传奇杯、冠绝杯按钮分别使用各自主题色系统
- 四个按钮的形制、留白、圆角和按钮骨架四态保持一致，只替换颜色强弱和文案状态
- 不允许在二级导航里塞入长说明、统计块、标题块或营销文案
- 4 个范围入口必须同高度、同圆角、同内边距；当前态可增加背景和强调边框，但不改变骨架尺寸
- 非当前态至少保留范围名，不得压缩成图标按钮或统一灰条
- 统计区只承载当前范围计数、阶段或资格摘要，不扩展成完整数据看板
- “全部”态下二级导航之后直接进入工作台；不得自动跟一个中性色 Banner
- 当前态与非当前态的层级差必须由底色 + 边框或底色 + 阴影共同建立，不能只靠文字颜色变化
- 当前态正文文字统一使用 text.primary.warm；副文案建议使用同色 72% 到 84% 透明度
- 非当前态按钮背景建议使用主题色 60% 到 78% 强度叠加弱描边，不得与当前态同亮度
- 整条二级导航的表面层级、亮度和阴影都必须弱于顶部导航；只允许当前态按钮局部增强，不允许整条导航整体抬成第二主块
- 二级导航、Banner、正文首块必须共用同一版心与外侧边界；不允许导航 1240、Banner 1200、正文 1160 这样逐层收窄，破坏首屏一体感
- 二级导航进入 Banner 或正文时优先使用连续底边、连续描边或连续阴影家族衔接；避免用 24 以上大留白把频道页首屏切成三段

具体设计方案：

- 桌面端默认值：按钮高度 40；导航行跟随频道主区内容宽度
- 紧凑桌面端：按钮高度 36；适用于正文首块本身较重的频道页
- 移动端默认值：按钮高度 32 到 40；允许换行但不改变单项骨架
- 默认表面：bg.surface.panel；描边 border.subtle；整条导航不使用杯赛主色满铺
- 当前态按钮：使用当前杯赛主题渐变或单色实底，叠加强调描边，文字使用 text.primary.warm
- 非当前态按钮：使用对应杯赛主题的低强度底色，透明度或饱和度显著低于当前态
- 分隔方式：按钮之间优先使用 8 到 12 的稳定 gap，不用整条容器和内分隔线制造范围带感
- 上下关系：Banner 如存在，Banner 到二级导航为 12 到 20；无 Banner 时二级导航到正文首块为 20 到 24
- 一体化推荐：顶部导航和二级导航使用直线拼接；Banner 改用同体系外轮廓但转入更柔和的底边；正文首块沿 Banner 底边直接接续，不另起新表面体系
- 一体化推荐：若正文首块为 8 + 4 主副栏，则 Banner 左右结构必须提前预告正文几何关系，让用户在进入内容前就感知左主区和右侧轨的秩序

展示解剖：

- 导航条：4 个固定顺序胶囊按钮。当前态最强，非当前态减弱，但四项始终同时可见
- 底边：二级导航必须直接与下方主工作台共边，或通过 1 条连续 gutter 进入 8 + 4 主副栏，不单独断开成第二个说明区

- 当前杯赛标题

- 当前杯赛资格 Badge
- 主工作台或主目录标题
- 右侧第一张身份或资格卡
- 当前态主题色回响位置

四态视觉映射：

- 全部：中性色按钮 + 全站目录语义 + 无 Banner
- 先锋杯：emerald / sky 色系按钮 + 对应 Banner + 新晋与入门赛道语义
- 传奇杯：violet / amber 色系按钮 + 对应 Banner + 成熟与秩序赛道语义
- 冠绝杯：rose / amber-deep 色系 + 高资格与荣誉赛道语义
