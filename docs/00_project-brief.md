# 今晚就来社区 / Project Brief

## 1. 项目定位

今晚就来社区是一个 Dota2 社区赛事门户。第一期先把比赛、选手、战队与身份归属做成稳定主线，第二期再补齐社区、内容、新闻、英雄等扩展内容；目标不是做资讯站，也不是把后台能力直接当产品门面。

文档入口约束：

- 第一期开发默认继续沿 01 到 13 阅读
- 第二期说明统一见 16_phase-two-features.md

产品核心形态：

- 第一期：社区赛事门户 + 荣誉归属平台
- 第二期：社区内容层 + 轻新闻与关系网

分期原则：

- 第一期聚焦比赛、赛季、选手、战队、我的与认领链路
- 第二期承接社区、内容、新闻、英雄及其运营关系网，具体范围与页面家族不再在本文件展开，统一见 16_phase-two-features.md
- 第二期能力不能反向挤压第一期的首要任务与信息层级

导航基线：

- 顶部第一层固定分为两组：左侧品牌与对象入口，右侧搜索 / 我的 / 后台工具入口
- 第一期导航结构明确采用“顶部对象入口 + 二级导航”：顶部对象入口负责对象维，比赛 / 选手 / 战队页内的页面级范围条负责杯赛范围切换
- 第一期对象入口固定为比赛 / 选手 / 战队；“我的”不并入对象入口，而是身份工具入口
- 全部 / 先锋杯 / 传奇杯 / 冠绝杯属于比赛、选手、战队频道内部的页面级范围条，也就是频道页的二级导航，不与顶部对象入口并列
- 这套导航默认结构是“顶部导航 + 条件性范围 Banner（仅具体杯赛态，可选） + 二级导航（页面级范围条） + 正文”；“全部”态不出 Banner，只有具体杯赛态才出现对应 Banner
- 比赛、选手、战队三个频道页的页面级范围条统一采用 community 风格的胶囊按钮行，出现在频道主区顶部而不是贴顶拼成整条范围带；Banner 如存在，位于其上方的频道页头部区域
- 首页左侧 3 栏只承担内容入口侧轨，不等同于全站顶部导航

## 2. 目标用户

核心用户：

- 第一期：正在参与或准备参与社区赛事的玩家
- 第一期：已在社区内有队伍、战绩、身份诉求的选手与队长
- 第一期：负责资料录入、审核和赛季维护的后台管理员
- 第二期：想追比赛、看战报、看人物与战队故事的观众
- 第二期：负责运营公告、活动、话题、招募和内容发布的社区组织者

次级用户：

- 第一期：需要快速了解规则、报名路径的潜在参与者
- 第二期：通过搜索、新闻、活动页首次进入站点的新访客

## 3. 网站目标

业务目标：

- 第一期：让用户快速理解“这里有稳定比赛、人物、战队和身份归属”
- 第一期：让游客能在 2 到 3 次点击内进入比赛或身份链路
- 第一期：让已登录用户快速回到“我”和“与我相关”的内容
- 第二期：让新闻、公告、活动、话题、招募和英雄内容统一回流到赛事主线
- 两期共通：让后台成为稳定的数据维护与审核入口，而不是前台的视觉副本

行为目标：

- 第一期：浏览比赛、赛季、选手、战队
- 第一期：注册、登录、绑定 Steam、提交认领
- 第二期：浏览社区、内容、新闻、英雄，并进入招募或活动链路完成参与决策；具体交互流统一见 16_phase-two-features.md
- 两期共通：后台完成审核、发布、回滚和高风险操作确认

## 4. 品牌关键词

- 深色竞技底盘
- 秩序感
- 荣誉感
- 社区参与感
- 叙事布局

## 5. 明确不要什么

- 不要大面积白底资讯站视觉
- 不要静态海报墙式首页
- 不要后台系统换皮后的冷数据库感
- 不要满屏发光、满屏重卡、所有区块都抢主视觉
- 不要脱离赛事与社区关系的通用门户模板
- 除首页外，其他页面都应保留明确版心；首页可以无版心，但不要为了做舞台感牺牲阅读效率和任务完成

## 6. 成功标准

体验成功标准：

- 第一期：用户进入前两屏内能明确感知比赛、人物、战队与身份入口
- 第二期：社区、新闻、英雄入口进入顶部对象入口、搜索、Footer 与详情侧栏的稳定回流链路，具体回流结构统一见 16_phase-two-features.md
- 首页能明显区分游客态与登录态
- 阅读页优先可读，操作页优先任务完成，后台页优先风险判断

系统成功标准：

- 页面结构、组件命名、视觉 token 和 CTA 口径在多页面保持一致
- 异步区域补齐 loading、empty、error、permission-denied 状态
- 深色主题下正文、链接与辅助文字达到 4.5:1 对比度底线
- AI 生成页面时能复用既有组件与规范，不再频繁漂移风格

## 7. 产品边界

前台覆盖：

- 第一期：首页
- 第一期：比赛、赛季、赛季结算、比赛详情
- 第一期：选手、战队
- 第一期：我的主页、认领历史、队伍管理
- 第二期：英雄、新闻与社区内容，统一见 16_phase-two-features.md

后台覆盖：

- 第一期：审核、赛事、赛季、选手、战队维护
- 第二期：发布、招募、活动、新闻与内容维护，统一见 16_phase-two-features.md

## 8. 默认设计判断

- 先业务，再结构，再内容，再视觉，再组件，再代码
- IA 先于 sitemap，sitemap 只负责把结构画出来
- 页面先定义唯一主任务，再决定主视觉与 CTA
- 优先复用现有共享骨架与组件，不为了“新鲜感”发明新模块
