# 今晚就来社区 / Wireflow And State Spec

## 1. 这份文档解决什么问题

- 静态 Blueprint 回答页面怎么排
- Wireflow / State Spec 回答用户做一件事时会经历哪些状态、看到哪些反馈、下一步去哪里
- 本文只保留状态规格方法和真实实例；第二期复杂交互统一见 16_phase-two-features.md

## 2. 哪些页面必须补状态流

- 登录、认领、补资料
- 搜索弹层
- 所有筛选与排序较重的频道页
- 含 Dialog、Sheet、Tabs、Accordion 决策流的页面
- 后台新建、编辑、发布、下线、回滚、批量处理

## 3. 标准写法

每个交互页至少定义：

1. 起点状态
2. 触发动作
3. 成功状态
4. 失败状态
5. 空状态
6. 权限状态
7. 危险状态
8. 移动端变化

## 4. 通用状态字段

| 状态 | 必须说明 |
| --- | --- |
| Loading | 正在加载什么，是否保留上一状态内容 |
| Empty | 为什么为空，用户还能去哪，是否有 CTA |
| Error | 用户可理解的错误说明，是否支持重试或回退 |
| Permission Denied | 为什么不能做，谁可以做，下一步是什么 |
| Success | 提示位置，是否跳转，是否局部刷新 |
| Danger Confirmation | 对象、结果、是否可恢复、二次确认动作 |

## 6. Herald Cup 专项补充

- 必须区分顶部对象入口、顶部工具入口和胶囊二级导航
- /matches、/players、/teams 在对象间切换时默认保留当前范围
- 首页内容入口侧轨只改变首页内部浏览与跳转，不冒充全站一级导航
- 高风险动作必须给出确认链路，不能只靠按钮颜色表达
- 本文中“当前范围模块强调层”统一指 Banner、标签、专题 CTA、工具条标题和右栏首卡的杯赛色表达；页面基础背景、卡片底、边框与正文文字仍跟随 Radiant / Dire

## 7. 验收清单

- 是否覆盖 loading、empty、error、permission-denied、success 和 danger-confirmation
- 是否写清状态切换而不是只列状态名
- 是否给出移动端交互变化
- 是否给出明确下一步，避免用户停在死路里

## 8. Herald Cup 真实状态实例

### 8.1 选手频道筛选工作台 /players

页面名称：选手频道筛选
交互目标：让用户通过分池、位置、战队、风格和搜索词快速缩小人物范围

起点状态：默认展示全部分池、全部位置、全部战队、全部风格，搜索词为空
触发动作：点击分池按钮；选择下拉项；输入搜索词；清空条件
成功状态：局部刷新焦点人物、结果计数和选手网格，不刷新整页
失败状态：保留当前筛选值和上一版结果，在工作台顶部显示“筛选失败，请重试”
空状态：显示空态卡，解释是当前组合无结果，并提供“清空筛选”入口
权限状态：无权限限制
危险状态：无

状态切换：
1. 默认态 -> 修改任一筛选 -> 本地 loading 态，结果区保留上一状态内容
2. loading -> 成功 -> 结果计数、焦点人物和网格同步更新
3. loading -> 空态 -> 焦点人物区隐藏，网格替换为空态卡
4. loading -> 失败 -> 回退到上一结果集并显示错误反馈
5. 任意筛选态 -> 点击清空 -> 回到默认态

移动端变化：
- 分池按钮组允许换行
- 下拉与搜索全部单列
- 焦点人物最多保留 2 张首屏露出

组件：
- SurfaceCard
- Form Field
- Button

### 8.2 第二期频道与社区状态流

- 新闻频道类型切换 /news 与社区首页公告、活动、话题导流 /community 的状态流统一见 16_phase-two-features.md。

### 8.4 搜索弹层 / Header Search

页面名称：站内搜索弹层
交互目标：从任何页面快速搜索选手、战队、比赛、新闻、公告、话题、活动和招募

起点状态：关闭态；点击搜索按钮或快捷键打开
触发动作：点击 Header 搜索；按 Cmd/Ctrl + K；输入关键词；点击最近搜索；点击结果；点击遮罩或 Esc 关闭
成功状态：展示左右两列分组结果，关键词高亮；点击结果后关闭弹层并跳转
失败状态：数据异常时显示错误说明和重试，不清空用户输入
空状态：无查询时展示快捷入口与最近搜索；有查询无结果时展示推荐入口和回流内容
权限状态：无权限内容不显示可操作 CTA
危险状态：无

状态切换：
1. 关闭态 -> 打开 -> 输入框自动聚焦，加载最近搜索
2. 打开未输入 -> 展示快捷入口、最近搜索、推荐对象
3. 输入关键词 -> 结果按实体与内容两列分组，最多显示每组 3-4 项
4. 有结果 -> 点击结果 -> 记录最近搜索，关闭弹层并跳转
5. 无结果 -> 展示“没有匹配结果”说明和推荐入口，不允许只显示一句空话
6. 按 Esc 或点击遮罩 -> 关闭并清空当前输入

### 8.5 比赛频道与淘汰赛详情 /matches 与 /matches/[slug]

页面名称：比赛频道与淘汰赛详情
交互目标：先在比赛频道快速识别赛程，再进入详情页读取单败淘汰对阵图

起点状态：比赛频道默认展示当前主推赛季分组；每条赛程仅展示名称、参赛队伍、进行中或已完赛状态
触发动作：点击品牌轮播；切换筛选；点击某条赛程；在详情页切换当前轮次关注点
成功状态：频道页局部刷新赛程分组；详情页显示 Battle Cup 风格 8 支队伍单败淘汰对阵图，并高亮当前轮次与结果
失败状态：保留上一版赛程或对阵图，同时显示“赛程加载失败，请重试”
空状态：频道页在当前筛选下无赛程时保留分组框架并提供“清空筛选”；详情页无完整对阵数据时显示“当前赛程尚未公布完整对阵图”并保留返回赛季入口
权限状态：无权限限制
危险状态：无

状态切换：
1. 频道默认态 -> 切换筛选 -> 局部 loading，保留当前赛季分组骨架和上一版结果
2. loading -> 成功 -> 分组与赛程行同步刷新，赛程行仍只显示名称、队伍、状态
3. 点击赛程 -> 进入详情页 -> 先显示 Hero 与摘要骨架，再加载淘汰赛对阵图
4. 详情 loading -> 成功 -> 对阵图按 8 进 4、半决赛、决赛顺序展开，并标记进行中与已完赛
5. 详情 loading -> 空态或失败 -> 保留返回赛季入口与简短说明，不回退为线性“第几场”流水列表

移动端变化：
- 频道页赛程行维持单列，只显示名称、队伍、状态
- 详情页对阵图允许横向滚动或按轮次分段，但轮次顺序仍必须保持 8 进 4 -> 半决赛 -> 决赛

组件：
- SurfaceCard
- Tabs
- Badge
- MatchSeasonGraphView

### 8.6 比赛工作台角色态右栏 /matches

页面名称：比赛工作台角色态右栏
交互目标：在比赛频道内，根据游客 / 普通用户 / 选手 / 队长以及当前范围切换右侧信息和动作

起点状态：默认根据当前登录态和角色渲染 visitor、user、player、captain 其中之一，并读取当前范围 all、pioneer、legend、crown 之一
触发动作：切换全部 / 先锋杯 / 传奇杯 / 冠绝杯；登录态变化；身份审核通过；建立队伍成功
成功状态：右栏与二级导航以下的频道模块强调层同步刷新，显示当前角色应见的信息、对应杯赛资格说明与跨频道动作；左侧比赛列表不改对象结构，但其表面层级同步切换到当前范围
失败状态：保留上一版右栏内容，并显示“身份信息加载失败，请重试”
空状态：某角色下当前子 Tab 无补充信息时，保留基础身份卡与说明卡，不整栏消失
权限状态：游客不显示身份动作；普通用户不显示建队和队长动作；选手不显示解散队伍；队长才显示危险动作
危险状态：队长点击“解散队伍”时必须进入 danger confirm Dialog

范围角色矩阵：

- 全部 / 游客：登录提示 + 全站比赛总览说明
- 全部 / 普通用户：基本用户信息 + 成为选手 + 去全站选手目录入口
- 全部 / 选手：基本用户信息 + 基本选手信息 + 建立队伍 + 去全站战队目录入口
- 全部 / 队长：基本用户信息 + 基本选手信息 + 基本队伍信息 + 去全站战队目录入口
- 某杯 / 游客：登录提示 + 当前杯赛说明
- 某杯 / 普通用户：基本用户信息 + 成为选手 + 去当前杯选手池入口
- 某杯 / 选手：基本用户信息 + 基本选手信息 + 当前杯赛资格说明 + 建立队伍
- 某杯 / 队长：基本用户信息 + 基本选手信息 + 基本队伍信息 + 当前杯赛资格说明 + 去当前杯战队池入口

频道关系态补充 /matches：

- 自己不是选手：右栏显示成为选手面板；如果当前有 pending claim，则以 pending 卡替换申请表单
- 自己是选手但未加入战队：右栏显示选手卡、建立队伍卡和当前赛道说明
- 自己是选手且当前战队属于当前赛道：右栏显示我的赛道上下文卡、当前战队卡以及进入我的人物页或战队页入口
- 自己是选手但当前战队不属于当前赛道：右栏显示“你当前不在该赛道”面板，说明当前战队归属和所看赛道不一致
- 比赛频道右栏不再显示泛化队长工具卡或解散队伍危险卡

右栏卡堆顺序：

- visitor / user：杯赛状态卡 -> 账号卡 -> 说明或申请卡
- player：杯赛状态卡 -> 账号卡 -> 选手卡 -> 建队卡
- captain：杯赛状态卡 -> 账号卡 -> 选手卡 -> 队伍卡 -> 跨频道动作卡 -> 危险卡
- claim pending：杯赛状态卡 -> 账号卡 -> pending 卡 -> 说明卡；pending 期间不显示建队 CTA

动作启用规则：

- 比赛频道右栏不直接承载邀请入队或训练赛邀请；这些动作统一放到 /players/[slug] 与 /teams/[slug]
- 当前杯赛下没有选手池或战队池数据时，跨频道入口保持可见，但说明为“当前杯赛暂无对象”
- 本人队伍上下文以“解散队伍”危险卡覆盖普通动作优先级，不并列显示两个主 CTA
- 任何动作提交成功后，只局部回写右栏和对应提示，不刷新左侧对象流顺序

状态切换：
1. 访客态 -> 登录成功 -> 普通用户态，显示基本用户信息与“成为选手”入口
2. 普通用户态 -> 申请通过 -> 选手态，显示基本用户信息、选手信息与“建立队伍”入口
3. 选手态 -> 建队成功 -> 队长态，显示用户、选手、队伍信息与“解散队伍”入口
4. 任一范围态 -> 切换胶囊二级导航 -> 保留滚动语义，同时替换 Banner、比赛工作台、右栏、工具条与回流区的模块强调层和上下文说明；二级导航始终位于 Banner 之上，且首屏始终只有这 1 个 Banner 槽位
5. 任一角色态 -> 切换胶囊二级导航 -> 左侧比赛工作台与右栏同步局部刷新，并整体切换为当前范围的模块强调层，不打断当前对象频道语义；二级导航仍保留 4 个固定入口，不退化成局部筛选器
6. 普通用户态 -> 提交成为选手申请成功 -> pending 态，右栏把“成为选手”替换为审核说明，并提供去 /my/claims 的入口
7. 队长态 -> 点击“去当前杯战队池”或“去当前杯选手池” -> 保持当前范围，切换到对应对象频道

比赛详情页补充矩阵 /matches/[slug]：

- 自己不是选手：右栏显示成为选手面板；如果当前有 pending claim，则同一位置改为审核中说明卡
- 自己是选手且当前所在战队属于这场比赛涉及到的队伍：右栏显示“我的比赛表现”面板；至少按小局列出英雄、KDA、对局结果和 1 条局内摘要；没有个人数据的小局明确写“暂未录入个人表现”
- 自己是选手但当前所在战队不属于这场比赛涉及到的队伍：右栏显示“您未参加当前比赛”面板，并提供回到本人战队或人物页的解释性入口
- 比赛详情页不再显示频道页里的建队、跨频道邀请或训练赛动作卡；详情页右栏只处理当前比赛与本人关系
- “我的比赛表现”面板的数据来源必须是选手级逐局表现记录；高光片段只作为补充说明，不得充当逐局数据本体

### 8.6A 选手页角色态右栏 /players 与 /players/[slug]

页面名称：选手页角色态右栏
交互目标：在选手频道或人物详情中，用右栏稳定解释“我是谁”“当前人物是谁”“我在对应杯赛里是否具备资格”“我能否邀请他入队”

起点状态：打开 /players 或 /players/[slug]，根据当前登录态、当前范围和查看对象生成右栏
触发动作：切换全部 / 先锋杯 / 传奇杯 / 冠绝杯；登录态变化；申请成为选手；建立队伍成功；切换人物；队长发起邀请入队
成功状态：右栏局部刷新，频道和详情页正文保持展示模式，不切成管理页；当前杯赛标题与资格标签同步更新
失败状态：保留上一版右栏卡堆，并提示“身份动作加载失败，请重试”
空状态：当前人物不可邀请时，动作卡保留解释，不整块消失
权限状态：游客不显示身份动作；普通用户只能申请成为选手；队长才显示邀请入队
危险状态：无

卡堆顺序：
1. 当前杯赛状态卡
2. 账号卡
3. claim pending 或选手卡
4. 队伍卡或建队说明卡
5. 当前人物动作卡

频道关系态补充 /players：

- 自己不是选手：右栏显示成为选手面板
- 自己有 pending claim：右栏显示 pending 卡和去 /my/claims 的入口
- 自己已绑定选手且未加入战队：右栏显示我的选手卡和建立队伍卡
- 自己已绑定选手且当前战队属于当前赛道：右栏显示我的选手卡和当前战队卡
- 自己已绑定选手但当前战队不属于当前赛道：右栏显示“你当前不在该赛道”面板，并提供进入我的人物页或战队页入口
- 选手频道页不直接发起入队邀请；邀请动作只保留在人物详情页

人物详情页动作矩阵 /players/[slug]：

- 自己不是选手：当前人物动作卡显示成为选手面板；不显示人物认领和队伍动作
- 自己已绑定当前选手：当前人物动作卡显示“这不是我”按钮面板；动作成功后当前账号回到普通用户态
- 自己已绑定其他选手：当前人物动作卡显示“您已绑定 XXX 选手”面板；不允许继续认领当前人物
- 自己未绑定选手且当前选手未认领：当前人物动作卡显示“认领该选手”面板；提交后右栏切到 pending 说明
- 当前选手已绑定其他用户：当前人物动作卡改为该用户基本信息面板；不显示认领 CTA

状态切换：
1. 游客或普通用户 -> 点击“成为选手” -> 打开 apply-player Dialog -> 成功后右栏切到 pending 卡
2. 选手态 -> 点击“建立队伍” -> 打开 create-team Dialog -> 成功后增加队伍卡，并把动作卡改成人物上下文说明
3. 队长看其他自由选手 -> 点击“邀请入队” -> 打开 invite-player Dialog -> 成功后动作卡改为“邀请已发送”反馈
4. 队长看本队成员或本人 -> 动作卡不显示邀请 CTA，只显示成员状态或当前身份说明
5. 任一状态 -> 切换胶囊二级导航 -> 列表标题、资格标签、筛选工具条、选手网格、右栏说明和回流区同步切换为“全站选手目录”或“某杯选手池”对应的模块强调层；切到具体杯赛态时在二级导航下方显示唯一的 Banner，切回“全部”时 Banner 消失；不得再保留第二个正文 Banner
6. 已绑定当前选手 -> 点击“这不是我” -> 进入确认链路 -> 成功后账号与当前人物解绑，右栏回到普通用户态
7. 未绑定选手且当前人物未认领 -> 点击“认领该选手” -> 提交认领申请 -> loading -> 成功后右栏切到 pending 说明，并记录到 /my/claims

移动端变化：
- 右栏在频道页和详情页都下沉到正文之后，但卡堆顺序不变
- 成功反馈优先以内联状态条展示，不额外插入 Toast 代替右栏回写

组件：
- SurfaceCard
- Badge
- Button
- Dialog

### 8.6B 战队页角色态右栏 /teams 与 /teams/[slug]

页面名称：战队页角色态右栏
交互目标：在战队频道或战队详情中，用右栏明确“我是否有队伍”“当前战队在对应杯赛里是否具备资格”“哪些动作属于本人队伍”

起点状态：打开 /teams 或 /teams/[slug]，右栏按 visitor、user、player、captain 之一渲染，并读取当前范围

成功状态：局部刷新列表、计数和当前筛选标签，批量动作执行后反馈明确
失败状态：保留当前筛选和值与上一版列表，并显示“操作失败，请重试”
空状态：当前筛选无结果时显示空态说明和清空入口
权限状态：无权限用户看不到批量动作；只读角色不能看到危险操作按钮
危险状态：批量下线、批量删除、批量驳回必须先二次确认

状态切换：
1. 默认态 -> 修改筛选 -> 局部 loading，保留上一版列表
2. loading -> 成功 -> 计数、列表和分页同步更新
3. 选择多行 -> 显示选中数量和批量操作条
4. 执行批量操作 -> Dialog 二次确认 -> 成功后刷新局部列表
5. 当前筛选无结果 -> 显示空态和清空筛选入口

移动端变化：
- Table 改卡片列表
- 批量操作条压缩到顶部工具条

### 8.14 后台编辑页保存、发布、下线、回滚 /admin/*

页面名称：后台编辑页
交互目标：让编辑者在一个稳定工作区里完成填写、保存、预览和风险操作

起点状态：进入新建或编辑页，表单和侧栏说明同时可见
触发动作：修改字段；保存草稿；发布；下线；回滚；离开页面
成功状态：保存成功反馈明确，必要时刷新预览或跳回列表
失败状态：保留用户输入和当前滚动位置，字段错误在就地显示
空状态：新建页无历史记录时显示“尚无审计记录”而不是留白
权限状态：只读角色只能看预览和历史，不能提交变更；危险操作仅管理员可见
危险状态：下线、回滚、删除必须在 Dialog 中写明对象名、影响和是否可恢复

状态切换：
1. 初始态 -> 修改字段 -> 表单进入 dirty 状态
2. 点击保存 -> loading，主按钮进入 loading 态但不改变布局
3. 保存成功 -> 顶部或按钮附近显示成功提示，预览同步更新
4. 保存失败 -> 保留输入并显示字段级或页面级错误
5. 点击发布/下线/回滚 -> 进入危险确认 Dialog -> 成功后刷新状态卡与审计记录

移动端变化：
- 侧栏说明和状态卡下沉到表单后
- 主按钮簇固定在表单尾部
- 风险操作固定在页面最底部

组件：
- AdminWorkspace
- Form Field
- AdminSidePanel
- Dialog

### 8.15 后台审核页通过与驳回 /admin/claims/[id]

页面名称：认领审核详情
交互目标：让审核者在对象信息、证据、历史记录和决策之间保持同屏可见

起点状态：审核详情已打开，显示申请人、目标选手、当前状态和历史记录
触发动作：点击通过；点击驳回；填写驳回原因；刷新状态；对象已被其他人处理
成功状态：状态更新为通过或驳回，记录写入审计历史，并给出返回列表入口
失败状态：保留当前表单和审核对象信息，显示“审核提交失败，请重试”
空状态：历史记录为空时展示“这是第一条处理记录”说明
权限状态：非审核角色不显示决策按钮，只保留只读信息
危险状态：通过或驳回前必须弹出确认框，明确对象和结果；驳回必须填写原因

状态切换：
1. 审核中 -> 点击通过/驳回 -> 打开确认 Dialog
2. 驳回 -> 必填理由 -> 提交成功后写入历史并更新状态标签
3. 通过 -> 确认后更新状态并提示用户已进入后续身份链路
4. 对象已被处理 -> 禁用动作区并显示状态已变更说明
5. 提交失败 -> 保留当前输入和对象信息，允许重试

移动端变化：
- 对象摘要卡保持在决策区之前
- 决策按钮改纵向堆叠
- 审计记录改时间线卡片

组件：
- AdminSidePanel
- Dialog
- Badge
- Form Field
